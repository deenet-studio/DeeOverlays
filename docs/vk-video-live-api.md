# VK Видео Live DevAPI

Этот документ фиксирует результаты аудита официальной документации VK Видео Live DevAPI на этапе 4. Источники: `https://dev.live.vkvideo.ru/docs/index` и раздел авторизации.

## Авторизация и параметры приложения

Используется OAuth 2.0 Authorization Code Flow.

1. Приложение создаётся в кабинете разработчика VK Видео Live.
2. Пользователь переходит на `https://auth.live.vkvideo.ru/app/oauth2/authorize` с `client_id`, `redirect_uri`, `response_type=code` и защитным `state`.
3. После callback сервер получает одноразовый `code` и меняет его на токены через `POST https://api.live.vkvideo.ru/oauth/server/token` с `grant_type=authorization_code`.
4. Обмен использует Basic-аутентификацию `client_id:secret`. Обновление выполняется этим же endpoint с `grant_type=refresh_token`.

`client_secret`, access token и refresh token являются секретами. В DeeOverlays они остаются только в памяти локального integration service и никогда не передаются в React, LocalStorage, URL Runtime или Git.

Для используемых read-методов документация указывает доступность «пользователь, приложение» и не требует отдельного scope. Права для других методов существуют, например `chat:settings`, `channel:credentials`, `channel:stream:settings`, но DeeOverlays их не запрашивает.

Для текущей локальной разработки в приложении VK зарегистрирован единственный redirect URI: `https://dev-overlays.deenet.ru/integration/vk-video/callback`. HTTPS-домен должен передавать этот запрос в локальный service на `127.0.0.1:8787` через настроенный владельцем туннель. Сам DeeOverlays не управляет VPS, DNS, SSL или туннелем.

## Подтверждённые возможности

| Возможность | Официальный метод | Решение DeeOverlays |
| --- | --- | --- |
| Текущий пользователь и канал | `GET /v1/current_user` | Определяем доступный канал после OAuth. |
| Информация о канале и текущем стриме | `GET /v1/channel` | Определяем состояние эфира и число зрителей. |
| Сообщения чата | `GET /v1/chat/messages` | Реализован polling раз в 4 секунды, `limit=50`, дедупликация по ID сообщения. |
| Число зрителей | поле `stream.counters.viewers` в `GET /v1/channel` | Реализовано обновление раз в 15 секунд. |
| Аватар и автор сообщения | ответ `GET /v1/chat/messages` | Передаются в нормализованном событии, если VK их вернул. |

Сообщение чата преобразуется адаптером в `OverlayDataEvent` с `sourceId`, `messageId`, именем и ID автора, текстом, временем и `avatarUrl`.

## Ограничения текущей интеграции

* Официальная документация подтверждает WebSocket-каналы и события платформы, однако для чата уже предоставлен документированный HTTP-метод. На этом этапе выбран более предсказуемый и щадящий polling; неофициальные WebSocket не используются.
* API не предоставляет личность каждого нового зрителя. Поэтому VK Видео не предлагается для виджета «Новый зритель».
* Официальный read API не подтверждает пригодное для DeeOverlays событие доната/поддержки. Донаты не подключаются.
* Платная подписка не подключается: для неё нет подтверждённого read-события в используемом наборе методов.
* Новый подписчик не подключается в локальной интеграции: у используемых read-методов нет события новой подписки. Он не эмулируется.
* При отсутствии активного стрима соединение остаётся успешным; редактор показывает понятное ожидание эфира.

## Ограничения запросов

`GET /v1/chat/messages` допускает до 200 сообщений за запрос. DeeOverlays запрашивает 50 и не чаще одного раза в 4 секунды. Проверка числа зрителей выполняется не чаще одного раза в 15 секунд. При временной ошибке сервис продолжает следующий запланированный запрос; после трёх ошибок статус становится «Ошибка» без агрессивного бесконечного reconnect.
