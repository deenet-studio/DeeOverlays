# Подготовка интеграций без backend

DeeOverlays готов к подключению реальных площадок на уровне интерфейса, конфигурации и Overlay Runtime.

## Что уже готово

* Единые идентификаторы источников: демонстрационные данные, VK Видео, YouTube, RuTube и Twitch.
* Общие статусы подключения и безопасная публичная информация о подключённом канале.
* Общий контракт `OverlayDataEvent`. Runtime получает события через синхронизацию DeeOverlays и не зависит от API площадки.
* Выбор источника данных в настройках виджета. Редактор не предлагает платформу для виджета, если у неё нет подходящего подтверждённого типа данных.
* Демонстрационные данные для проверки редактора и OBS без внешних сервисов.

## Что намеренно не запускается до server stage

OAuth, хранение и обновление токенов, запросы к API, WebHook, polling и переподключение. Эти функции требуют публичного HTTPS endpoint и серверного хранения секретов; их нельзя переносить в React или Browser Source.

## Порядок будущего server stage

1. Разместить DeeOverlays Integration Backend на защищённом HTTPS-поддомене.
2. Указать callback URL каждой платформы в её кабинете разработчика.
3. Подключать адаптеры по одному после отдельного аудита официального API: сначала VK Видео, затем отдельными задачами YouTube, RuTube и Twitch.
4. После каждого адаптера включать в Editor только реально поддерживаемые виджеты и события.

Пока сервер не размещён, реальные источники намеренно показываются как «Требуется сервер». Это исключает ложное подключение и искусственные ошибки.
